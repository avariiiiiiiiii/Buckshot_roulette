## Часть 2. План реализации (черновик, ждёт утверждения)

Статус: ТОЛЬКО ПЛАН. Кода нет. Технические допущения ниже помечены [проверить] — их нужно подтвердить на реальной установке игры (версия, декомпиляция), а не принимать на веру.

### 2.0 Стек

- Загрузчик: BepInEx 5 (Mono, Unity) [проверить версию игры/рантайма].
- Сеть: игра на Photon PUN 2 → все сетевые объекты (моб, предметы) — через PhotonView/RPC; хост (MasterClient) — источник истины по логике моба и патронам.
- Библиотека контента: REPOLib (регистрация префабов врагов, предметов магазина, ценностей, уровней) [проверить актуальный API].
- Ассеты: Unity-проект с теми же версией Unity и пайплайном, что у игры → AssetBundle (модель дилера, дробовик, ножовка, банка пива, телефон, сигареты, лекарство, наручники, глушилка, иконки, звуки).
- Музыка: "General" by Bleyzi — треки из BR лицензированы автором; нужно проверить условия использования/разрешение для распространения мода [вопрос].
- Декомпиляция игры (dnSpy/ILSpy) для изучения: Enemy*, EnemyDirector, ItemAttributes, ValuableObject, PlayerHealth, PlayerController (stamina), shop (ShopManager), PhysGrabObject, ItemGun.

### 2.1 Модули (вертикальные срезы)

1. **core** — плагин, конфиг, логирование, регистрация контента, сетевые константы.
2. **shells** (общая "магазинная" логика патронов) — класс `ShellMagazine`: список патронов (live/blank), `Load(rand)`, `Peek()`, `Pop()`, `LiveRatio`. Используется и дилером, и новым дробовиком.
3. **dealer** — враг: ИИ-стейт-машина, модель/анимации, музыка, оверлей патронов, урон.
4. **items** — дробовик, ножовка, адреналин, наручники, глушилка.
5. **valuables** — пиво, телефон, сигареты, лекарство.
6. **hud** — оверлей зарядки (как у бабушки/Gnome-hands-face-эффект), индикатор.

### 2.2 Дилер (враг)

**Спавн.** Регистрируем EnemySetup в пуле нужного уровня сложности; при старте раунда игра выбирает врагов — дилер входит в тот же ролл. Размещение: на любой карте (навмеш уже есть у всех уровней).

**Магазин патронов.** В момент решения о спавне хост генерирует магазин (N live + M blank, например 3+2), рассылает по RPC всем клиентам. Вероятность выстрела боевым = live/(live+blank) на текущий момент (0.6 при 3/2). После каждого выстрела патрон «вынимается» → пересчёт. Когда пуст — перезарядка: новый магазин + повтор анимации у всех.

**ИИ (состояния):**
- Patrol — быстрый обход навмеша, играет музыка (3D-звук, привязан к дилеру, радиус слышимости).
- Notice — игрок замечен (зрение/слух по паттерну других врагов).
- Chase — преследование цели.
- Shoot — на дистанции/в LOS: прицеливание → выстрел текущим патроном из очереди. Live → урон игроку; blank → эффект без урона. Патрон расходуется.
- Reload-cooldown / Retarget — после выстрела в игрока дилер переключается на другого игрока (по твоему ТЗ — «после попытки выстрела в одного игрока начинает искать другого»). Перезарядка дробовика — когда магазин пуст.
- Cuffed — модификатор (см. 2.4): атаковать нельзя, ходить можно.
- Dead — HP 100, вылет лута/эффекта [вопрос].

**Получение урона дилером (кроме нового дробовика).** Любой урон по нему проходит через «ролл патрона дилера»: берём патрон из ЕГО магазина? Или отдельный магазин «игрока»? — см. вопросы. Эта развилка влияет на архитектуру.

**Урон по дилеру.** Харвестим точку входа урона врага (Enemy health: `EnemyHealth.Hurt(...)` [проверить]) через Harmony-патч: если цель — дилер, то ролл live/blank; blank → урон 0 + звук/эффект.

**Оверлей.** При спавне (и при каждой перезарядке) у ВСЕХ игроков поверх экрана — анимация зарядки: патроны видны (красные = live, синие = blank) вставляются в дробовик; в конце показано соотношение. Хук — как у "руки на лице" у бабушки (Gnome/Hidden-подобная UI-сцена в HUD) [найти конкретный префаб/скрипт].

### 2.3 Предметы магазина

Каждый — `Item` (REPOLib) с префабом, иконкой, ценой, лимитом, батареей/зарядами.

| Предмет | Цена | Заряды | Суть |
|---|---|---|---|
| Новый дробовик | ½ цены gun shotgun | энергия как у gun shotgun, одинаковый расход | 100 урона, магазин случайный на каждую перезарядку, обычные мобы — всегда live, дилер — ролл по его правилу |
| Ножовка | 2–5к | 1 | ×2 урон любого оружия; дробовик реально обрезается, остальным — визуальное изменение (если получится) |
| Адреналин | 5–10к | 1 | 10 реальных секунд: время для всех, кроме пользователя, замедляется |
| Наручники | 15к | 1 | на моба с руками, только вблизи: он больше не может атаковать до конца игры, ходит |
| Глушилка | 35–40к | 3 | ультразвук: звукореагирующие мобы убегают от неё на расстояние d/2 |

**Реализация по предметам:**
- *Дробовик*: свой `ItemGun`-подобный компонент; общий `ShellMagazine`; патч урона.
- *Ножовка*: флаг-множитель урона на оружии (`damageMultiplier = 2`) + визуальный меш/масштаб для видимого эффекта. Дробовик — реально укорачиваем ствол (подмена меша).
- *Адреналин*: локальный Time.timeScale нельзя (глобальный). Вместо этого: для остальных — «замедление» через множители скорости (враги: NavMeshAgent speed/animator speed; игроки: PlayerController speed + анимации + физика предметов) [риск: физика Rigidbody не масштабируется простым множителем], у пользователя — компенсация. Нужен общий `LocalTimeScale` сервис.
- *Наручники*: у врага список «рук» (флаг `HasHands`, по префабу/конфигу); при наложении ставим `Cuffed=true` → отключаем атакующие состояния. Проверка дистанции через Physics.OverlapSphere/raycast.
- *Глушилка*: по использованию собрать всех врагов в зоне, у которых есть реакция на звук (`EnemyOnScreen`/`Investigate` вызовы), и для каждого выставить точку отступления: `target = enemyPos + (enemyPos − usePos).normalized × (dist/2)`, где dist — расстояние от моба до глушилки. Радиус действия — вопрос.

### 2.4 Ценности (Valuables)

Через `ValuableObject`: цена, физика, префаб, спавн в пулах уровней.
- *Пиво*: use по E в руке → +10% maxHP, стамина = 100%, дебафф «головокружение» (эффект камеры N сек). Банка остаётся с той же ценой и сдаётся на квоту.
- *Burner phone*: триггер касания → один раз проигрывается роботизированный голос с именем ближайшего врага (нужны записи/TTS для каждого имени врагов, либо собираемое из слогов). Один раз за жизнь объекта.
- *Сигареты*: E → +10% HP, не тратятся? [вопрос: одноразовые?]
- *Лекарство*: E → 50% +20% HP / 50% −10% HP, цена сохраняется.

### 2.5 Сеть и синхронизация

- Хост рассчитывает всё случайное (магазин дилера, исход «лекарства», ролл дилера при попадании) и рассылает результат (RPC). Клиенты ничего не роллят сами.
- Состояние моба: позиция/анимация — через стандартный синк врагов игры; наши данные (магазин, Cuffed, HasTarget) — через RPC / custom properties.
- Предметы: использование — RPC на хост → хост применяет → рассылка эффекта.
- Мод должен быть нужен у всех игроков (как большинство контентных модов) [подтвердить].

## Часть 3. Ответы пользователя (утверждённые правила)

Нумерация — по вопросам из чата.

1. Магазин патронов общий для дилера и всех игроков.
2. Единица «выстрела» — каждое нажатие курка (E). Автоматического оружия в R.E.P.O. нет.
3. Холостой: имитация выстрела без урона; звук громкий, привлекает внимание ВСЕХ мобов, но не тянет их прямо к точке выстрела.
4. Дилер стреляет попыткой (не обязательно попадание). Сразу после попытки уходит гулять по карте как другие мобы, в того же игрока повторно не стреляет. После попытки ищет другого игрока.
5. Живой патрон по игроку: 100 урона (по умолчанию у игрока 100 HP).
6. Смерть дилера: только орб, как у других мобов.
7. «Все игроки мертвы» — вопрос снят (игра заканчивается).
8. Зрение/слух/скорость дилера — по моему предложению: чуть быстрее обычного бегуна, потеря цели через несколько секунд.
9. Музыка — только в радиусе вокруг дилера (3D-звук).
10. Несколько дилеров возможны, количество — по штатным вероятностям игры.
11. Новый дробовик: в магазине столько патронов, сколько выпало (например 8, из них 3 холостых). Перезарядка забирает столько же энергии, сколько у gun shotgun при 5 патронах.
12. Игроки видят состав патронов только в анимации появления дилера (порядок неизвестен). Если дилера нет или стреляют не по дилеру — все патроны живые.
13. Ножовка: максимум ×2, повторно не стакается; усиление спадает после выстрела, потом ножовку можно применить снова; применима к любому предмету.
14. Адреналин: коэффициент 0,1. Падающие предметы и физика тоже замедляются. Предмет, который держит пользователь, работает нормально, тащится нормально. Игрока можно схватить и спасти.
15. Наручники: список мобов с руками — искать в коде/документации. Пример без рук: голова (кусает ртом). Дилер в наручниках ходит и играет музыку.
16. Глушилка: подтверждено, d/2.
17. Пиво/сигареты/лекарство: повторно использовать нельзя; после использования сдаются на квоту по той же цене.
18. Имя монстра — отображаемое на текущем языке игры (русский и английский); озвучка тем же роботным TTS, что у чата.
19. Головокружение от пива: 10 секунд, эффект как тошнота в Minecraft.
20. Ассетов нет: искать в интернете, иначе делать в Blender. Права на музыку у автора запрошены, разрешение получено.
21. Мод нужен всем игрокам.
22. Версия — последняя, Steam, BepInEx установлен.
23. Цены нормальны.

## Часть 5. Факты из декомпиляции (сборка 26294889, REPOLib 4.2.0)

Источник: ilspycmd-декомпиляция `Assembly-CSharp.dll` и `REPOLib.dll`, два отчёта субагентов (все ссылки file:line — относительно декомпилята). Префабы и значения ассетов (цены, enemyName, кривые) в коде отсутствуют — читаются в рантайме.

### Регистрация контента
- Предмет: `Items.RegisterItem(ItemAttributes)`; ключ в `StatsManager.itemDictionary` — имя ассета (`Item.name`), должно быть уникальным. ## Часть 7. Состояние на 2026-11-09 и что делать в следующий раз

### Как сейчас устроены патроны (код, не ТЗ)
- **Общий пул** (`Shells/ShellPool`, ведёт хост): один на уровень, 2..8 патронов (`MagazineMin..Max`), минимум 1 боевой и 1 холостой. Создаётся при появлении дилера или дробовика дилера на уровне. Пустой пул сразу заменяется новым, у всех показывается анимация (`ShellOverlay`, только счётчики, без порядка).
- **Кто тянет патрон:** выстрел дилера; первое попадание каждого выстрела любого оружия игрока по дилеру (`DealerDamagePatches` + `Logic/ShotLedger`: дробины одного выстрела и тики одного луча делят патрон, ближний бой — окно 0,35 с на стрелка); каждое нажатие курка дробовика дилера на уровне.
- **Мимо пула:** выстрелы дробовика дилера вне уровня (меню, фургон, магазин) и его самопроизвольный выстрел (всегда боевые); взрывы, удары предметами, яма.
- **Дробовик дилера:** патроны = полосы батареи; полос = размер текущего пула; при смене пула сохраняется процент заряда, а не число патронов. Боевой — ванильный `ShootRPC` (6 дробин × 17 = 102 урона), холостой — `BlankRPC` (полоса, щелчок, дымок). Холостой сжигает ножовку.

### Открытые проблемы механики (ждут решения пользователя)
1. **Счётчик дробовика живёт отдельно от пула.** Полосы — доля от размера пула, а не остаток. Выстрелы дилера и попадания по нему полосы не меняют. Пример из лога 2026-11-08: в пуле 3, на ружье 4 из 4; пул опустел, на ружье ещё 1 из 4, и этот патрон взят уже из нового пула.
2. **Смена пула съедает или добавляет патроны.** `Resize` пересчитывает через процент, игра округляет `Mathf.RoundToInt` к чётному: 1 из 4 → пул на 2 → 0 патронов; 1 из 8 → пул на 2–3 → 0; 3 из 8 → пул на 4 → 2.
3. **Документы противоречат друг другу.** ТЗ 2.1 («по обычным мобам всегда настоящими») и ответ 12 («если стреляют не по дилеру — все живые») против журнала (8) (дробовик берёт из пула при любом выстреле). Код сделан по журналу (8).
4. **Не объяснено:** в логе 2026-11-08 дважды «Дробовик заряжен» сразу после смены пула (2 из 2, потом 2 из 6). Зарядки в коде мода не найдено — спросить, заряжал ли пользователь ружьё; если нет — расследовать.
5. Мелкое: клиентам по сети уходит порядок патронов (`ShellPool.Raise`), на экране только счётчики.

Варианты решения пунктов 1–2 (рекомендация — первый):
- **А. Полосы = остаток общего пула** (одно ружьё на всех, как в Buckshot Roulette; буквально ответ 1). Выстрел дилера и попадание по нему снимают полосу у всех дробовиков. Расхождение и округление исчезают. Нужно заново решить, что значит энергия/зарядка (ответ 11).
- **Б. Оставить проценты, починить округление** (при ненулевом заряде минимум 1 патрон). Расхождение «на ружье 4, в пуле 1» остаётся.
- **В. Свой магазин у каждого дробовика** (ответ 11 буквально), общий пул — только дилер и попадания по нему. Откат решения из журнала (8).

## Часть 8. Исправление цикла пула (2026-11-14)

- Уточнено: батарея дробовика — личный запас выстрелов; общий пул определяет результат попадания по дилеру и выстрела дилера. Выстрелы по обычным врагам общий пул не расходуют. Не считать разные значения батареи дробовика и общего пула багом.
